# 文本与真实艾特

`native_text` 后端开放文件传输助手、好友、群聊的文本收发，以及真正的群成员艾特。

## 文本发送

在插件里调用：

```python
ctx.send_text("filehelper", "你好，helper")
ctx.reply(message, "已收到你的消息")
```

`ctx.reply` 回复消息所属会话，并核对原消息的连接会话，避免断线重连后把旧回复发到新账号。主动发送使用会话 ID，不能使用显示昵称。

文本应为 1–1023 个 UTF-8 字节，且不能包含 NUL。中文通常占多个字节；文本发送还会应用本地配置中的长度随机等待。

## 网页文字引用与微信引用接收

聊天页文字气泡下方的“引用”按钮可以选中本次消息或历史文字；输入框上方显示引用预览，支持取消。
发送确认框显示最终完整文字，以 `「引用 名字：原话」` 加正文发送；引用原文最多取 200 个字符，和正文合计仍受 1023 UTF-8 字节限制。
这是现有文本通道的**文字引用**，不是微信原生引用卡片，也不会自动艾特被引用的人。

微信接收到的 `appmsg/type=57` 引用回复会转成带引用原话的 type 1 文本，正常显示、记录并参与上下文。
引用机器人时按引用对象的微信 ID 触发回复，不靠显示昵称；对应会话仍须开启自动回复。
引用图片、语音或文件时只保留类型占位，不将其中的 XML、下载地址或密钥带进模型。原生引用发送接口尚未实现。

机器人成功发出的群聊和私聊文字均在发送入口立即补记，不依赖原生回传，刷新网页后历史记录也能显示。
本机微信客户端手动发送的普通文字也通过原生发送采样进入同一队列，核对当前账号后标记为自己发送，正常显示；开启长期记忆的会话也会记录。普通自己发言不会触发自动回复自己，既有明确控制指令规则不变。此入口需要更新后的原生 DLL，不等于保证手机同账号同步或读取微信历史。
原生回显与发送通知按次配对，只显示一次；早先没有记录下来的发言不会从微信聊天库自动补回。
2026-10-24 已通过模拟发送、回显乱序、引用 XML、上下文及隔离 Chrome 页面交互检查；未向真实微信会话发送测试消息，真实 type 57 收取仍需现场验收。

## 群成员艾特

```python
if message.is_group:
    ctx.reply_at(message, "收到，这是一条真正的艾特回复")
```

真实艾特的通知目标使用成员 ID，可见标签优先使用成员在本群的 `/绑定` 称呼，其次使用微信联系人缓存的名字。不能通过只在普通文本里拼接 `@昵称` 获得真实通知。

主动发送时可指定一位或多位群成员；显示昵称和真实通知目标分别传入：

```python
if message.is_group:
    rows = ctx.group_members(message.chat_id, expected_session=message.session_id)
    member = next((row for row in rows or () if row["wxid"] == message.sender_id), None)
    if member is not None:
        ctx.send_at_text(message.chat_id, "请查看这条消息", [member["wxid"]],
                         expected_session=message.session_id,
                         display_names=[member["nickname"] or member["wxid"]])
```

`members` 与 `display_names` 按顺序对应，一次支持 1–8 位成员；昵称每个最多 64 字符。正文与生成的标签合计不超过 1023 个 UTF-8 字节，使用消息的 `session_id` 可防止重连后发送旧任务。未提供 `display_names` 时以 wxid 作为可见标签。

网页也支持真实艾特：进入“群聊与会话 → 发送消息”，刷新会话、选择群并勾选成员，再填写正文发送。网页会在发送前重新核对成员名单并使用当前群昵称；普通好友会话不提供艾特选项。完整流程见[网页管理台](../guide/web-panel.md#发送文字和艾特成员)。

群成员缓存加载失败只影响艾特选择，不阻止普通文字发送；发送连接失效仍会阻止发送。

需要的能力声明：

```json
{
  "api": "v1",
  "description": "文本和群艾特示例",
  "message_types": [1],
  "requires": ["text.receive", "text.send", "group.text.mention"]
}
```

## 收到的消息字段

| 字段 | 含义 |
| --- | --- |
| `message.type` | 文本为 `1`，普通图片为 `3` |
| `message.text` | 文本正文 |
| `message.chat_id` | 当前会话 ID，群以 `@chatroom` 结尾 |
| `message.sender_id` | 实际发言者 ID |
| `message.is_group` | 是否来自群聊 |
| `message.is_self` | 是否是当前账号同步来的消息 |
| `message.session_id` | 消息所属框架连接 |
| `message.data` | 消息附加字段快照 |
| `message.data["sender_role"]` | 实时群消息作者身份：`owner`、`admin`、`member` 或 `unknown` |

插件默认只收到文本消息。框架只处理实际收到的实时消息，不补拉停机时的旧消息。

### 本机发送回传与历史拼接

- 普通文字及引用回复的本机监听可能先于服务器 ID 到达。框架在同一连接内，按账号、会话、作者与相反来源，在 10 秒内逐次关联；普通文字比较完整正文，引用比较被引用消息 ID 与回复正文（两通道统一忽略回复首尾空白），不比较显示昵称。连续发送相同内容仍按次数保留。后到的 ID 只补充首次记录，不再次进入普通回复插件或模型记忆。
- 引用缺少原消息 ID 时不猜测跨通道对应关系；引用不同消息但回复同一句话、普通文字恰好写成“引用某某”的样子，都不会相互合并。已经存在的重复记录不会自动删除。
- 这是缺少本机服务器 ID 时的有界关联，不是跨设备的绝对唯一性证明；缺失回传、超过时间窗口，或不同设备同时发送完全相同的文字，仍可能无法准确关联。两个已知且不同的服务器 ID 不会合并。
- 网页历史与实时消息按服务器 ID 或连接内事件身份合并，不再舍弃边界附近两秒的消息。发送入口使用负事件序号，原生事件使用正序号；无身份的旧记录不凭正文猜测合并。
- 原生文本后端在发送前将负事件序号关联到此次发送标记。确认回传携带服务器 ID 时，按账号、会话、连接和发送序号补写原发送记录；回传先到时暂存 ID，成功发送入库时一并保存。不会为补 ID 新插入消息、覆盖已有不同 ID，或批量猜测旧记录的 ID。
- 历史页展示有大小上限的文字/引用预览，超长处明确提示；每行序列化后不超过 8 KiB，200 行可安全通过进程间响应限制。原文库及后台引用来源仍保留完整正文；加载失败会提示并允许重新选择会话重试。
- 旧记录不会批量删改。下次正常打开记录库时自动补建 `(account, room, id)` 查询索引，无需清空记忆。

同步接收的普通长文字使用 V5 大缓冲，最多容纳 262143 个 UTF-8 字节（包含群消息的作者前缀），不会在 1023 字节处整条丢弃或截断半个汉字。原文库保留接收全文；网页和模型上下文仍按各自已有上限显示/截取，不等于原文丢失。主动发送文字的 1023 字节限制未改变。

群内身份取自当前连接最近 30 秒内读取的群缓存，约每 15 秒检查；无法确认、缓存过期或连接变化时为 `unknown`。主动查询可使用 `ctx.group_member_role(room, wxid, expected_session=message.session_id)`。这只是身份信息，不自动赋予插件管理权限，详见[群成员与身份](../guide/friends-and-groups.md#群内身份和真实艾特)。
