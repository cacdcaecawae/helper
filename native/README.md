# 原生消息适配

当前适配 Windows x64 微信 4.1.15.13 / 4.1.15.56；使用前核对 `compatibility.json` 中的核心文件指纹。加载前按文件大小与 SHA-256 匹配构建，原生端还核对已加载映像的 PE 标识；未知构建会拒绝加载。

运行需要的组件：

- `text_service.py`：文件传输助手、好友、群聊的原生文本、图片、文件附件服务及表情、语音发送。
- `filehelper_service.py`：接收通道和服务公共实现。
- `run_selftest.py`：进程、版本、远程调用与桥接生命周期封装。
- `core_version.h`：按精确构建解析原生地址，调用、虚表校验和 Hook 卸载共用同一份映射；`wxbot_framework/native_profiles.py` 提供对应的只读账号、缓存地址和表情解码参数。
- `bridge_watchdog.py`：主程序异常退出后的隐藏清理守护入口，运行时需要一起保留。
- `build_text/text_bridge.dll`：当前消息收发和真实艾特桥接。
- `emoticon_send.h`：本地 GIF 的原生类型 47 发送，含账号核对、文件限制和共享引用清理。
- `voice_send.h`：语音对象构造与原生类型 34 发送，入口为 `WxSendVoice` / `WxInspectVoicePath`；排队前复制音频字节，沿用任务存活和安全卸载检查。
- `file_download.h`：普通文件附件的 CDN 下载，入口为 `WxDownloadFile`；按声明大小和完成大小校验，原始 CDN 参数不写入报告。
- `file_send.h`：普通文件附件发送，入口为 `WxSendFile` / `WxInspectFilePath`；排队前复制字节，使用微信自己的 InputTemp 路径供上传任务读取。
- `friend_receive.h`：独立好友验证接收通道，仅复制实时申请，跳过历史初始化记录；沿用 V3 内存队列。
- `friend_request.h`：`WxInspectFriendRequest` / `WxAcceptFriendRequest`，核对账号并等待微信原生验证结果；申请凭据不写报告。
- `group_management.h`：原生邀请好友进群及创建群聊，创建成功时读取服务器返回的群 ID；未进行真实群管理操作测试。
- 群系统消息 `10000/10002` 不作为普通聊天正文；完整群成员和真实群昵称由 `wxbot_framework/group_members.py` 只读获取，`group_events.py` 负责变动确认与去重。
- 当前接收通道为 `WxPollMediaMessageV5`，在 V4 的元数据缓冲区后追加 64 位微信原始消息编号，以十进制字符串传给 Python，保留 V1–V4 调用方的缓冲区边界。普通消息与独立系统 XML 入口共同提供撤回关联；新增 Hook 沿用回调计数和正常卸载流程。管理台保留原记录，`anti_recall` 插件控制自动补发。
- `build/selftest_bridge.dll`：兼容文件传输助手后端。

源码 `text_bridge.cpp` 复用 `selftest_bridge.cpp` 的公共结构、任务调度和清理逻辑，因此两个源文件都要保留。`vendor/` 中只保留编译所需的 MinHook 源码、头文件和许可。

原始调试器、逆向数据库、跟踪日志、探针可执行文件、旧版本 DLL、编译中间产物和历史版本均不属于本目录。

重新编译使用 `build_bridges.ps1`；正常使用已提供的两个 DLL 时无需编译。账号和群聊从根目录的本地配置读取，没有预置真实用户。

4.1.15.56 已实测账号发现、文本发送、其他账号发来的群文本、撤回通知与原消息 ID 关联，以及桥接正常加载和卸载。媒体、好友验证和群管理入口已完成静态地址及布局核对，本轮未逐项重做真实网络操作。

`manual_text_receive.h` 补充本机微信 UI 手动发送普通文字的入口：在已登记的发送函数中复制目标和正文，原调用及引用所有权不变；返回状态被接受后写入原有 V5 消息队列，不写日志或聊天数据库。Python 重新核对登录账号后作为自己发送的文字处理，统一显示、记忆及自己消息的分发规则。有原始消息编号时按编号去重，不按相同正文删除真实重复发言。`reserved` 位 8 表示本机发送，位 16 表示长文字使用 V5 大缓冲区。Hook 沿用公共回调计数和卸载流程。

本机发送采样已通过合成 C++ 消息对象、原生队列和 Python 映射测试；它不代表对方已收到消息。同账号从手机发送的同步文本仍不保证被目前的来信入口捕获，不能将本机发送监听描述成完整的手机历史同步。

2026-10-24 已在 4.1.15.56 更新桥接并恢复连接，由用户自己在本机微信手动发送普通文字；确认网页收到本机发送事件、方向为自己发出，原文库对应记录恰好一条。操作方未代发测试消息，微信未退出。此次样本没有提供服务器消息编号，因此仅确认该实机样本的显示与单次入库，不据此承诺手机同步或所有跨入口去重场景。

更新原生桥接时先使用 `build_bridges.ps1 -Target text -StageOnly` 编译到 `.build/staged`；停止所有使用旧桥接的机器人、确认 DLL 已卸载后，再替换正式 DLL 并重新启动后台工作进程。不要直接覆盖微信正在使用的 DLL。

2026-10-25 同步接收的 `type=1` 也支持 V5 大缓冲：小于 1024 字节仍使用 `text`，更长内容放入 `image_xml` 并设置 `reserved` 位 16（不设置本机发送位 8）。Python 按位 16 取完整正文，而不再要求同时属于本机发送。ABI、消息类型及服务器消息 ID 不变；大缓冲上限为 262143 个 UTF-8 字节（包括群作者前缀），越界或无效对象不发布残缺正文，不在接收线程栈上分配大数组。`tests/native_text_receive_test.cpp` 直接调用真实采样/队列代码，以合成对象覆盖 341/342 个汉字、1023/1024 字节、emoji、群消息、上限及无效长度。与 `native_manual_text_test.cpp`、`native_quote_send_test.cpp` 一起编译为隔离 EXE 验证，不加载微信。

## 原生引用（4.1.15.56 私聊文字首版）

2026-10-24 在精确指纹的 4.1.15.56 上，由用户手动进行私聊原生引用回复，已确认发送 Hook 捕获 `49/57`：仍是文字对象虚表 `0x9026b48`，回复正文为 `+0x758` 的字符串，被引用消息嵌入在 `+0x248`，存在标记为 `+0x688`。不能把它当普通文件对象，也不能把引用原话里的 XML 当成本次回复的 XML。`reserved` 位 32 携带仅含偏移、长度、布尔值的布局诊断，不保存对象转储。

本轮还只读核对了该用户指定消息在原生缓存中的序列化结果：`refermsg` 含 `content/createtime/displayname/fromusr/svrid/msgsource/type/chatusr`，回复、原话、作者 ID 及引用服务器消息 ID 相互对应；原始 XML 和内存对象未落盘，未代发测试消息。此私聊样本不代表群聊字段和网页原生发送已验证。

注意区分对象类型：该版本缓存消息数据对象（虚表 `0x8f704b8`）的 `+0xb8` 是服务器消息 ID，`+0xc8` 是毫秒时间，`+0xe0` 是正文。发送用文字对象的 `+0x148` 属于字符串布局，不能把其前八字节当成服务器 ID。后续发送端应使用真实消息 ID、核对账号及会话，不得用网页行号或 JS Number 代替。

`quote_send.h` 提供 `WxInspectQuote` / `WxSendQuote`，ABI 为 18344 字节的 `QuoteConfig`。限定私聊、原消息类型 1、真实 uint64 消息 ID、作者属于该会话，未知构建和群聊均拒绝，不自动降级。引用文字快照只用于再次核对，不再手工填写一个默认消息对象冒充完整原消息；`created_at` 保留 ABI 兼容，不用它覆盖微信原消息的时间。

**实机失败记录：**旧版本构造检查曾通过，但用户通过网页实发时出现 `stage=92 / exception=0xc0000005`。旧阶段 92 混合服务获取和发送，报告未输出异常位置，不能据此断言具体出错指令。旧检查在获取发送服务之前就返回，且手工拼装的 `MessageData` 缺少 `+0x2c0` 的原生类型数据，构造通过不代表可发送。此前通过的旧检查不能作为修复后发送成功的证据。

**修正路径（仅精确 .56 指纹）：**静态核对客户端引用加载回调 `0x19fd480`：在应用任务队列 `0x30f450` 上，通过 `0x17da070(manager, optional_typed, chat, server_id, 0)` 查询原消息，结果是有所有权的 `0x2e8` 字节类型数据（存在标志 `+0x2e8`），再用 `0x183b690` 转换成完整的 `0x440` 字节 `MessageData`。桥接复用这条路径，不再持有扫描得到的裸指针，也不自行打开或解密微信聊天数据库。核对原消息及嵌套类型数据的 ID、作者、收件人、会话、正文后，才交给引用构造函数 `0x3a1b050`。临时原生对象按对应的析构函数释放；引用对象保留自己的所有权。

新 `quote_probe` 包括服务获取、原消息查询、完整性校验和引用构造，但**绝不调用发送函数**。阶段分别为：90 账号上下文、91 服务提供者、92 消息管理器、93 原消息查询、94 转换、95 校验、96 引用构造、97 发送前检查、98 调用发送、99 发送返回。诊断版本 2 记录是否调用发送、原消息完整性、模块相对异常位置和独立的清理异常，不记录正文、原始 XML、原消息 ID 或堆地址。Python 不再接受旧版只构造外壳的成功报告。

离线回归 `tests/native_quote_send_test.cpp` 使用全桩函数验证查询/清理生命周期、无发送检查、原消息缺失、跨会话、缺失内部对象、账号切换、各阶段异常与发送状态；不会加载微信。**修正版本已安装，通过实机无发送检查；随后用户明确确认，网页实发在微信中显示为原生引用卡片。**只读核对本项目原文库，也确认新增发出消息为 `native_type=49`，包含结构化引用及回复正文，引用 ID 与原消息一致。实发确认来自用户观察，存储核对来自本地数据库；目前仅验证了此 .56 私聊文字场景，未在第二台电脑实测。

本次旧桥接安全卸载返回 `ERROR_BUSY (170)`，用户退出对应微信后才替换，并校验安装文件哈希。用户重新登录后，用此前失败的私聊原消息进行 `quote_probe`，结果为 `stage=97 / source_found=true / source_complete=true / built=true / send_called=false / sent=false / exception=0 / cleanup_exception=0`，清理返回 0，DLL 已卸载，项目原文库哈希未变，检查期间机器人后台保持关闭。安装需停止机器人并确认旧 DLL 卸载，不能覆盖正在运行的 DLL，不能未经用户同意自动重连或代发测试消息。

其他用户复现需使用 Windows x64、项目支持的精确 4.1.15.56 核心文件指纹，以及配套的新 Python/网页代码和 `native/build_text/text_bridge.dll`。按项目通常流程绑定自己的账号即可；引用路径没有硬编码本机账号或数据目录。当前发送范围仅私聊中引用普通文字；原消息必须仍能由微信查询，缺少 ID 的旧记录另受下述缓存匹配限制。发行时须包含新增的引用模块、原生头文件与更新后的 DLL，不能仅发布前端或遗漏未跟踪文件；跨机器及其他微信版本仍需分别验证。

本机收到私聊文字引用时，位 64 表示有界结构化快照；Python 再核对作者属于本账号/私聊对方，补全名称后转成统一引用消息。群聊及非文字引用尚未验证此本机对象布局，继续只监控诊断，不冒充完整原文。

项目自身的 `messages` 表增量增加 `native_message_id TEXT`、`native_type INTEGER`、`quote_json TEXT`。`text` 保留兼容的可读全文；`quote_json` 是版本 1 的回复正文与引用快照（作者 ID、显示名、原消息 ID、类型、原话），不保存原始 XML、msgsource 或下载密钥。引用仍是一条消息，不会把原话重新算成作者的新发言。给模型的有界投影优先保留回复正文，原文库中的快照不跟随模型截断修改。旧行默认空引用和空 ID，不从旧的拼接文字猜造原生引用信息。

### 旧记录缺少 ID 时禁止文字降级

已移除页面把“引用某某”拼入普通文字的旧分支。网页只提交本项目消息行的引用（`quote_ref`），后台按账号及会话重新读取原文；行号不是微信 ID，不会直接传给原生入口。群聊或不支持的消息禁用引用，不能借旧的文字引用按钮冒充卡片。

旧私聊文字若没有微信 ID，`quote_references.py` 只读当前绑定微信的缓存：限定已核对的 .56 数据对象、同一会话、同一作者、完整相同正文、接收时间前后 10 秒内的原生创建时间。缓存中的多个对象副本可对应同一条消息；出现不同 ID、缓存缺失、账号变化或超过 3 秒/512 MiB 预算则失败，不挑最近一条、不改发文字、不读取微信聊天数据库。只有唯一确认后才回填本项目该行的 ID，清空/原文变化则取消。

该流程已对用户指定的旧私聊原文进行实机只读核对：唯一消息 ID 与先前核对结果一致，创建时间与入库时间相差约 1.125 秒。本次核对未修改项目数据库、未发消息、未启动后台。发送入口仍须由用户重新启动项目后确认实发效果；此前已经发出的拼接文字不会自动变成引用卡片。
